# 요구사항정의서

## 1. 프로젝트 개요

본 프로젝트는 대학교·공공기관의 부속 홈페이지 운영을 가정한 PHP 기반 통합관리 CMS입니다.

여러 학과, 연구소, 부속기관 홈페이지를 하나의 관리자 시스템에서 관리할 수 있도록 하며, 관리자 역할에 따라 사이트, 메뉴, 페이지, 게시판, 첨부파일, 배너, 팝업 등을 관리할 수 있도록 구현합니다.

## 2. 개발 목적

* PHP 기반 웹서비스 구축 경험 확보
* 홈페이지 CMS 구조 이해
* 관리자 화면과 일반 방문자 화면을 모두 포함한 웹서비스 구현
* DB 설계부터 기능 구현, 테스트, 문서화까지 전체 개발 흐름 경험
* 웹에이전시/SI 환경에서 자주 요구되는 홈페이지 구축 및 유지보수 기능 구현

## 3. 사용자 유형

### 3.1 최고관리자

전체 CMS를 관리하는 관리자입니다.

* 전체 사이트 관리
* 관리자 계정 관리
* 관리자 역할 관리
* 전체 게시판 및 페이지 관리
* 관리자 작업 로그 확인

### 3.2 사이트관리자

특정 부속 홈페이지를 담당하는 관리자입니다.

* 담당 사이트 관리
* 담당 사이트의 메뉴 관리
* 담당 사이트의 페이지 관리
* 담당 사이트의 게시판 관리
* 담당 사이트의 배너 및 팝업 관리

### 3.3 콘텐츠관리자

게시글과 페이지 내용을 관리하는 실무 담당자입니다.

* 게시글 작성/수정/삭제
* 게시글 첨부파일 업로드
* 일반 페이지 내용 수정

### 3.4 일반 방문자

관리자 권한 없이 홈페이지를 조회하는 방문자입니다.

* 홈페이지 조회
* 게시글 조회
* 게시글 검색
* 첨부파일 다운로드

## 4. 기능 요구사항

### 4.1 관리자 인증

* 관리자는 아이디와 비밀번호로 로그인할 수 있다.
* 비밀번호는 해시 처리하여 저장한다.
* 로그인한 관리자만 관리자 페이지에 접근할 수 있다.
* 로그아웃 시 세션을 종료한다.

### 4.2 역할관리

* 관리자는 역할에 따라 접근 가능한 기능이 달라진다.
* 최고관리자는 모든 관리 기능에 접근할 수 있다.
* 사이트관리자는 담당 사이트의 기능만 관리할 수 있다.
* 콘텐츠관리자는 게시글 작성과 페이지 수정 중심의 기능만 사용할 수 있다.

### 4.3 사이트 관리

* 최고관리자는 부속 홈페이지를 생성할 수 있다.
* 사이트명, 사이트 코드, 설명, 사용 여부를 관리할 수 있다.
* 사용 중지된 사이트는 일반 방문자 화면에 노출하지 않는다.
* 사이트관리자와 콘텐츠관리자는 담당 사이트만 관리할 수 있다.

### 4.4 메뉴 관리

* 사이트별로 메뉴를 생성할 수 있다.
* 상위 메뉴와 하위 메뉴를 구성할 수 있다.
* 메뉴명, 연결 유형, 노출 여부, 정렬 순서를 관리할 수 있다.
* 메뉴는 일반 페이지, 게시판, 외부 링크 중 하나와 연결할 수 있다.

### 4.5 페이지 관리

* 일반 페이지를 생성, 수정, 삭제할 수 있다.
* 일반 페이지는 학과소개, 인사말, 오시는 길처럼 비교적 고정적인 콘텐츠를 의미한다.
* 페이지 내용은 관리자 화면에서 입력한다.
* 페이지 수정 시 이전 내용을 페이지 수정 이력으로 저장한다.
* 이전 버전의 내용을 확인할 수 있도록 한다.

### 4.6 게시판 관리

* 공지사항, 자료실, FAQ 게시판을 관리할 수 있다.
* 게시글을 작성, 조회, 수정, 삭제할 수 있다.
* 게시글 목록에서 검색과 페이징을 제공한다.
* 중요 공지글은 상단 고정이 가능하다.

### 4.7 첨부파일 관리

* 게시글에 첨부파일을 등록할 수 있다.
* 1차 개발에서는 첨부파일을 게시글에만 연결한다.
* 업로드 가능한 확장자를 제한한다.
* 저장 파일명은 난수화하여 파일명 충돌을 방지한다.
* 일반 방문자는 첨부파일을 다운로드할 수 있다.

### 4.8 배너 관리

* 사이트별 메인 배너를 등록할 수 있다.
* 배너 제목, 이미지, 연결 URL, 노출 기간, 사용 여부를 관리할 수 있다.
* 노출 기간과 사용 여부에 따라 일반 방문자 화면에 배너를 표시한다.

### 4.9 팝업 관리

* 사이트별 팝업 공지를 등록할 수 있다.
* 팝업 제목, 내용, 노출 기간, 사용 여부를 관리할 수 있다.
* 노출 기간과 사용 여부에 따라 일반 방문자 화면에 팝업을 표시한다.
* 1차 개발에서는 텍스트 팝업을 기준으로 설계한다.

### 4.10 페이지 수정 이력

* 페이지 수정 시 수정 전 제목과 내용을 저장한다.
* 수정자와 수정 일시를 함께 저장한다.
* 하나의 페이지는 여러 개의 수정 이력을 가질 수 있다.
* 1차 개발에서는 페이지 수정 이력만 관리하고, 게시글 수정 이력은 향후 검토 사항으로 둔다.

### 4.11 관리자 작업 로그

* 관리자 로그인, 등록, 수정, 삭제 등 주요 작업 이력을 기록한다.
* 작업자, 작업 유형, 작업 대상, 작업 일시, IP 정보를 저장한다.
* 관리자 작업 로그를 통해 누가 언제 어떤 작업을 했는지 확인할 수 있도록 한다.

## 5. 비기능 요구사항

### 5.1 실행 환경

* PHP 8.x 환경에서 실행 가능해야 한다.
* MySQL 또는 MariaDB를 사용한다.
* Docker Compose 기반 실행 방법을 제공한다.
* README에 설치 및 실행 방법을 문서화한다.

### 5.2 DB 접근

* DB 접근은 PDO를 사용한다.
* SQL Injection 방지를 위해 Prepared Statement를 사용한다.
* DB 접속 정보는 `.env` 파일로 관리하고, GitHub에는 `.env`를 커밋하지 않는다.

### 5.3 인증 및 보안

* 비밀번호는 평문으로 저장하지 않는다.
* 비밀번호는 PHP의 비밀번호 해시 기능을 사용하여 저장한다.
* 로그인하지 않은 사용자는 관리자 페이지에 접근할 수 없다.
* 역할에 따라 접근 가능한 관리자 기능을 제한한다.

### 5.4 첨부파일 보안

* 업로드 가능한 확장자를 제한한다.
* 업로드 파일 크기를 제한한다.
* 저장 파일명은 난수화한다.
* 실행 가능한 파일 확장자는 업로드를 허용하지 않는다.

### 5.5 유지보수성

* 프로젝트 폴더 구조를 기능별로 정리한다.
* 요구사항정의서와 DB 설계 문서를 함께 관리한다.
* 주요 기능 구현 후 README에 실행 방법과 화면 캡처를 추가한다.
* 변경 가능성이 있는 기능은 향후 검토 사항으로 분리한다.

## 6. 1차 개발 범위

1차 개발에서는 아래 기능을 우선 구현합니다.

* 관리자 로그인/로그아웃
* 관리자 역할관리
* 부속 홈페이지 관리
* 메뉴 관리
* 일반 페이지 관리
* 게시판 관리
* 게시글 첨부파일 업로드/다운로드
* 배너 관리
* 팝업 관리
* 페이지 수정 이력 관리
* 관리자 작업 로그 기록
